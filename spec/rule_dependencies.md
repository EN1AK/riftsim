# 规则依赖顺序（spec/rule_dependencies.md）

> 阶段 1 交付物。定义游戏状态、阶段、窗口、行动、结算、效果之间的**判定与应用依赖顺序**，
> 作为阶段 2 架构（状态机/legal_actions/结算循环）与阶段 3 实现顺序的依据。
> 引用格式：`R-CR-xxx`（规则）/ `MECH-xxx`（spec/rule_semantics.yaml 机制）。
> 全局前提：卡面 > 规则（R-CR-2）、"无法" > "可以"（R-CR-54）、尽可能执行（R-CR-55）。

## 1. 状态组件构建依赖（reset 的构造顺序）

```
卡组合法性（MECH-DECK-CONSTRUCTION, R-CR-103）
 → 玩家与循环回合队列（R-CR-115）
 → 区域模型（MECH-SPACES/BOARD/NONBOARD-ZONES, R-CR-105..109）
    └─ 隐私矩阵随区域建立（MECH-PRIVACY, R-CR-128/129）
 → 传奇区/英雄区落位（R-CR-111/112）
 → 战场选择与放置（MECH-MODE-DUEL, R-CR-485：各备3随机选1，RNG-1）
 → 双牌堆洗牌（R-CR-114，RNG-2/3）→ 各抽 4（R-CR-116）→ 依次调度（R-CR-117）
 → 起始玩家开启首回合（R-CR-118）
```

约定：所有 RNG 消费按固定顺序（战场选择 → 洗牌 A → 洗牌 B → 调度随机回收入底顺序）
从单一 seed 派生，replay 时按同序重放。104 为 Setup 引导条，不产生独立步骤。

## 2. 状态派生依赖（任意时刻的只读推导）

| 派生量 | 依赖 | 规则 |

| 可行动玩家 | 四态 → 优先权（普通窗口）/焦点（对决窗口） | R-CR-311..313、R-CR-347 |
| 物体最终属性 | 印刷值 → Layers 层1特质 → 层2技能 → 层3加减（依赖→时间戳） | R-CR-473..480 |
| 单位致命判定 | 最终战力（Layers 后）- 累积伤害 ≤ 0 | R-CR-143、R-CR-323.3.b |
| 控制/争夺 | 战场在场单位归属 + 对决/战斗结算结果 | R-CR-190、R-CR-466 |

## 3. 行动合法性判定顺序（legal_actions / step 校验链）

对任何候选行动，按以下顺序求值，任一失败即非法（不产生部分状态）：

1. **未决任务门**：存在未决任务（清理/FEPR/结算中）→ 玩家行动抑制（R-CR-334..336、R-CR-320/321）。
2. **窗口门**：四态+优先权/焦点归属（R-CR-310/311/313/347）→ 决定本玩家当前可发起的行动类别
   （自决 / [迅捷] / [反应]；R-CR-806.1.c、R-CR-813.1.c）。
3. **时机权限门**：默认=己方回合开环；[迅捷]扩至法术对决、对方回合；[反应]扩至闭环；
   单位/装备主动技能另限主阶段（R-CR-145.2/151.2/381）；条件性权限在步骤 5 复核（R-CR-806.4.b/813.4.b）。
4. **对象门**：来源在场/区域合法（R-CR-380）、目标合法且数量精确（R-CR-355.6/355.10）、
   位置选项（基地/控制战场；伏击/游走/待命扩展——R-CR-822/810/811）。
5. **费用门**：总费计算（基础→额外→增→减→总调，≥0；R-CR-356）+ 支付能力
   （符文池特性匹配、[E]来源活跃、弃置/回收可完成——R-CR-357/416.3/444）。
6. **结算前复核门**：打出的步骤 5（R-CR-358），失败全撤销并回起始区域。

## 4. 结算顺序依赖（引擎主循环的不变量）

从高到低优先级，任何高层存在时低层不得执行：

```
未决任务（TASKS）                      R-CR-332/333/334
  └─ 清理（CLEANUP 本身是任务；清理中禁 FEPR）   R-CR-318..324、R-CR-320
链上待处理项 → FEPR 循环               R-CR-336..340
   确认(按加入序) → 执行(可加反应) → 让过(全员连续) → 结算(最新已确认项)
   特例：单位/装备牌与获得资源技能确认后立即结算   R-CR-337.2/400.2/429.2
   结算中抑制清理                      R-CR-321（清理转未决）
对决/战斗未决标记 → 由清理 9/10 步骤开启  R-CR-323.9/10、R-CR-344
战斗内部固定序：步骤1法术对决 → 步骤2伤害 → 步骤3结算（插3c/3d）  R-CR-463..466
触发入链序：同玩家自选；跨玩家自回合玩家起按回合序        R-CR-383.3.d.1
战斗攻守触发序：进攻方 → 非防守方回合序 → 防守方       R-CR-464（383.4 联动）
```

顺序约束的**相互抑制**：清理∥FEPR（320）、结算∥清理（321）、移动/召回/贴附不经链（446/456/434）。
清理中若新满足清理条件：本次清理完后立即再清一次（322）——引擎必须支持清理迭代直至无未决。

## 5. 效果应用顺序（Layers 与替换）

效果冲突裁决次序：

1. **卡面优先**（R-CR-2）与**"无法"优先**（R-CR-54）先行。
2. **替换效果**：事件执行前替换该事件；每事件每个替换限一次（370.2）；
   多替换→受影响方控制者排序（372）；多事件→逐个处理（373）。
3. **Layers 持续效果**：层1 特质（含战力赋值、复制）→ 层2 技能（含贴附效果文本并入）→
   层3 加减（先增后减、非被动带限快照、负增视为0、贴附战力加成在此）。
   层内：依赖关系优先（被依赖先）→ 时间戳（早先应用；未激活失时间戳）。
   循环重评至收敛（476）。
4. **触发**：入链后才可能被反应；入链顺序按 §4。

## 7. 得分/胜负终止链

```
确立控制（对决/战斗结算）→ 清争夺 → 征服检查（470/471 限制判定）
开始阶段计分步骤 → 据守检查（同上限制）
得分事件 → 更新「本回合各战场得分」标记 → 下一清理 323.1 胜利检查
终分限制（471.1.b）：仅征服且当前分 ≥ 胜利分-1 → 须本回合已在每战场得分，否则改为抽 1
终局路径：胜利检查 / 效果指示获胜 / 认输（649..652）/ 燃尽终局（431.3.c.1）
```

## 8. 隐藏信息依赖（训练观察隔离）

1. 隐秘信息（牌堆顺序、对手手牌、对手待命牌内容）**永不**进入 `observe()`、
   `legal_actions` 参数化、公开 trace（R-CR-128）。
2. 待命牌的 [反应] 属性与牌面内容对对手不可见（R-CR-811.6.a）：UI/观察仅显示「存在一张待命牌」。
3. 特权视图（全知）仅离线调试/回放使用，与玩家视图严格分文件/分通道。
4. 效果需要的隐藏区选择（调度、洞察、随机弃置）必须通过确定性 RNG 或该持有者自决完成，
   不得经由对手可见信道泄露选择内容。

## 9. 实现顺序锁定（阶段 3 的构建序）

模块落地顺序沿用 docs/implementation_scope.md §5 拓扑，此处锁定不可调换的硬依赖：

```
区域/隐私 → 物体与卡定义 → 组卡校验 → Setup/RNG → 资源/费用 → 四态与优先权 →
阶段/清理骨架 → 链 + FEPR → 六步打出 → 移动/召回 → 战斗三步 → 得分/终局 →
认输 →（P1）Layers/替换/触发注册表/关键字子集 →（P1）Token/计数标
```

横切：黄金法则三件套（000 章）从第一行代码就作为全局裁决函数存在；
事件/trace 挂钩点在本文件 §4 每一层边界预留（阶段 2 契约细化）。
