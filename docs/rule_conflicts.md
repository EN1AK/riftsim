## 1. 效力层级原则（冲突裁决协议）

按 AGENTS.md §0 规定的层级，并标注其在规则库内的锚点：

1. 官方 Errata > 2. 官方 FAQ/裁定/解释 > 3. 官方规则书（Core Rules）。
   规则库内对应元规则：`R-CR-508`（FAQ 冲突处理原则）、`R-CR-509`
   （裁定偏差：只要裁定继续有效，其优先于规则书文本）、`R-CR-510`（FAQ 与核心规则关系）。
2. 同级冲突：先核适用范围与生效日期；同级同版本英文优先于中文
   （例外：中文资料为更新且具有官方效力的裁定）；其他相同取较新版本。
3. **禁止**把卡牌数据库文本、博客或模型推断当作高于官方规则的权威。
4. 无法判定的矛盾：写入 `docs/unresolved_rules.md` 并阻断相关实现，不猜测。

效力拓扑细节（含过渡性 FAQ 降级原则）：见 `docs/source_inventory.md` §2。

## 4. 冲突处理流程（阶段 3 起生效）

1. 实现中发现疑似冲突 → 先查 `rules.db` FTS 与 rule_evidence 是否有 authority 更高的条文；
2. 仍为冲突 → 按 §1 协议裁决；同级不可裁决 → 登记 unresolved 并冻结相关实现；
3. 每次裁决须记录：冲突规则 ID 双方、候选解释、适用层级、最终依据（来源+日期+语言）、被覆盖条目；
4. 裁决结果回填本表；影响语义的同步更新 `spec/rule_semantics.yaml` 的重跑生成器。
